# SolidLoom 可运行世界与通用管理系统需求规格

> 状态：需求梳理中。
>
> 实现状态：本文新增能力均为 `planned`，不代表当前版本已经可用。
>
> 产品边界：SolidLoom 是通用工具，不是固定的工厂、公司、家族、宗门或国家管理游戏。

## 1. 产品目标

SolidLoom 需要从三维建模工作台演进为一套本地优先的“可运行世界构建工具”：用户能够创建模型和场景，自定义世界中的实体、状态、关系、动作与规则，然后在独立运行视图中游玩、观察、管理，或把受控语义能力提供给 Agent。

同一套平台应当能够搭建完全不同的工程：

| 工程 | 实体 | 关系 | 状态 | 资源 | 流程与规则 |
| --- | --- | --- | --- | --- | --- |
| 赛博工厂 | 员工、机器、工位 | 任职、占用、隶属 | 体力、压力、设备状态 | 资金、原料、产品 | 工作、生产、维护、结算 |
| 家族管理 | 成员、住宅、产业 | 血缘、婚姻、继承 | 健康、忠诚、声望 | 财产、土地、人脉 | 成长、联姻、继承、经营 |
| 修仙宗门 | 弟子、长老、洞府 | 师徒、门派、敌对 | 境界、灵力、心境 | 灵石、丹药、贡献 | 修炼、突破、炼丹、宗门任务 |
| 国家模拟 | 人口、机构、行政区 | 管辖、联盟、贸易 | 稳定度、满意度 | 预算、粮食、能源 | 政策、税收、建设、外交 |

如果增加上述任一工程都需要修改 SolidLoom 通用实体类型、动作状态机或数据库核心表，说明抽象仍然不够通用。

## 2. 平台与工程边界

```text
SolidLoom 平台
├─ 模型、材质、关节和动画编辑
├─ 场景组合与资产引用
├─ 领域定义包加载与版本管理
├─ 通用实体、组件和关系图
├─ 状态、动作、流程、规则和事件运行时
├─ 时间、调度、物理、导航和交互
├─ 通用资源账本、指标与查询投影
├─ Agent 控制租约和语义动作接口
├─ 游戏视图和管理视图框架
└─ 本地存档、事件日志和迁移

工程领域包
├─ 定义工程中的实体种类
├─ 定义组件字段和派生状态
├─ 定义关系种类和约束
├─ 定义资源、指标和目标
├─ 定义动作、流程和规则
├─ 定义角色、权限和 Agent 能力
├─ 配置游戏 HUD 与管理页面
└─ 提供模型、场景和初始运行配置
```

平台只提供表达、运行、持久化和展示领域概念的机制。具体概念由工程领域包定义，不能硬编码进平台共享层。

## 3. 核心设计原则

- **领域无关**：平台内核只认识通用原语，不认识员工、公司、灵石、国家或工资。
- **本地优先**：工程、存档、事件和 Agent 控制默认运行在本机。
- **声明式优先**：常见领域逻辑通过 schema、条件、效果和视图配置表达，不要求修改核心代码。
- **引用而非复制**：场景引用资产；工程自行决定运行实例何时升级引用版本。
- **编辑与运行分离**：资产和场景定义不保存运行中的动态状态。
- **同源交互**：玩家、管理页面和 Agent 使用同一动作校验与规则执行链路。
- **React 与 3D 分工**：3D 渲染世界和空间反馈，React 渲染状态、按钮、HUD 与管理界面；二者通过同一运行时状态连接。
- **效果可追溯**：状态、关系、资源和指标变化都要能追溯到动作、流程或系统事件。
- **并发安全**：动作和资源变更支持修订校验、幂等键、租约和 fencing epoch。
- **可迁移**：领域包和资产升级必须有版本与迁移策略，不能静默破坏存档。
- **能力诚实**：未实现能力必须标记为 `planned`。

## 4. 通用领域原语

### 4.1 实体

实体是运行世界中拥有唯一身份的对象，例如一个人、一台机器、一块土地、一个部门、一项政策或一个宗门。

平台实体只固定以下元数据：

```ts
interface RuntimeEntity {
  id: string
  typeId: string
  domainPackageId: string
  components: Record<string, unknown>
  revision: number
  createdAt: string
  updatedAt: string
}
```

平台不能为实体固定 `employeeId`、`companyId`、`cultivationLevel` 等领域字段。

### 4.2 组件

组件是一组由领域包定义、可校验、可查询的字段。组件定义至少包含：

- 唯一类型标识和版本。
- JSON Schema 或等价字段约束。
- 默认值。
- 字段读写权限。
- 编辑器和管理视图显示元数据。
- 是否持久化、派生或临时。
- 迁移函数标识。

平台可提供通用可选组件，例如变换、模型引用、碰撞体和控制租约，但工程决定实体使用哪些组件。

### 4.3 关系

关系是带类型和属性的有向边：

```ts
interface EntityRelation {
  id: string
  typeId: string
  sourceEntityId: string
  targetEntityId: string
  attributes: Record<string, unknown>
  revision: number
}
```

领域包能够声明：

- 关系方向。
- 一对一、一对多或多对多基数。
- 允许连接的实体类型。
- 是否互斥、唯一、对称或可传递。
- 创建和删除条件。

任职、血缘、师徒、隶属、联盟、占用和管辖都应由同一关系机制表达。

### 4.4 状态属性

状态属性描述实体当前情况，例如健康、压力、设备温度、稳定度或灵力。状态可以是：

- 持久状态。
- 短期状态。
- 根据表达式计算的派生状态。
- 带阈值和滞回区间的离散状态。

平台负责校验、更新和查询；字段语义由工程定义。

### 4.5 资源

资源是可以被拥有、预留、转移、产生或消耗的量。领域包定义：

- 资源类型和单位。
- 是否可分割。
- 是否允许负数。
- 是否需要守恒。
- 可以存放在哪类资源容器中。
- 预留、提交和释放规则。

资金、粮食、原料、产品、灵石、丹药、政治资本和家族财产都可以使用通用资源账本，但它们不是平台内置字段。

### 4.6 指标

指标用于表示不可直接转移的数值、聚合结果或评分，例如：

- 公司估值。
- 家族声望。
- 宗门影响力。
- 国家稳定度。
- 场景完成度。

指标可以由事件累积，也可以由查询表达式动态计算。指标与资源必须区分：声望通常不能像现金一样预留和转账。

### 4.7 动作

动作是某个主体对自身、目标或世界发出的有持续时间的语义请求。动作定义包含：

- 参数 schema。
- 主体和目标类型约束。
- 前置条件。
- 权限要求。
- 占用通道。
- 生命周期和可中断策略。
- 开始、进行、完成、取消和失败效果。
- 幂等与重试策略。

“工作”“联姻”“修炼”“颁布政策”都是工程动作，不是平台硬编码动作。

### 4.8 流程

流程是跨越多个动作或时间阶段的长周期状态机，例如生产订单、继承、修炼突破或政策实施。流程定义包含：

- 阶段和阶段转移。
- 每阶段进入和退出条件。
- 参与实体和角色槽位。
- 超时、暂停、失败和补偿策略。
- 进度与产出。

### 4.9 规则

规则以“条件—效果”表达：

```text
when <event or schedule>
if <condition expression>
then <effects>
```

首期通用效果至少包括：

- 设置或增减组件字段。
- 添加或移除关系。
- 预留、提交、释放或转移资源。
- 增减指标。
- 启动、暂停、取消流程。
- 创建或销毁授权范围内的实体。
- 发出新的领域事件。

首期优先支持声明式规则。任意脚本扩展属于后续能力，并且必须经过沙箱、权限和资源限制。

### 4.10 事件

事件记录已经发生的事实。每个事件至少包含：

```ts
interface DomainEvent {
  id: string
  typeId: string
  runId: string
  sourceEntityId?: string
  sourceActionId?: string
  payload: Record<string, unknown>
  occurredAt: string
  simulationTime: number
  idempotencyKey?: string
}
```

事件用于审计、派生指标、触发规则、构建查询投影和回放。

### 4.11 目标

目标描述运行实例希望达成的条件，可以属于玩家、Agent、组织或整个工程。目标由条件表达式、进度、期限、奖励和失败条件构成。

## 5. 领域包

领域包是 SolidLoom 通用能力与具体玩法之间的边界。

“领域包”首先是一种由 SolidLoom 工具创建、编辑、校验和导出的可序列化工程资产，不等同于需要程序员编写的 npm 包或插件。用户应当能够在创作工作台中配置实体类型、组件、关系、动作、规则和管理视图，再将它保存为工程内领域包或可复用模板。

首期领域包以声明式数据为主；只有声明式机制确实无法覆盖的高级能力，后续才考虑受限代码扩展。

```ts
interface DomainPackageManifest {
  id: string
  version: string
  entityTypes: string[]
  componentTypes: string[]
  relationTypes: string[]
  resourceTypes: string[]
  metricTypes: string[]
  actionTypes: string[]
  processTypes: string[]
  ruleSets: string[]
  viewDefinitions: string[]
  migrations: string[]
}
```

领域包必须：

- 使用命名空间避免类型冲突。
- 声明兼容的平台版本。
- 声明自身数据版本和迁移路径。
- 能够被禁用、升级和导出。
- 不允许绕过平台权限直接修改数据库。
- 不允许覆盖其他领域包的类型，除非显式声明扩展关系。

一个工程可以组合多个领域包，例如“基础角色包 + 建筑交互包 + 赛博工厂经营包”。

## 6. 资产、场景与运行实例

### 6.1 资产

资产使用局部坐标并可复用：

- 模型、材质和纹理。
- 角色、骨骼和动画。
- 对象模板和交互锚点。
- 可复用场景片段。

### 6.2 场景

场景使用世界坐标保存：

- 资产或对象模板引用。
- 实例变换和允许覆盖的参数。
- 地面、房间、碰撞和导航配置。
- 实体初始关系。
- 领域包绑定和场景变量。

### 6.3 运行配置

运行配置引用场景和领域包，并提供领域 schema 所需的初始数据。平台不预设“初始资金”或“员工列表”等固定字段。

### 6.4 运行实例与存档

运行实例保存动态事实：

- 实体组件状态。
- 关系图。
- 动作和流程状态。
- 资源账户与指标。
- 动态物体位置。
- Agent 控制租约。
- 事件日志和快照。

运行实例不得反向污染资产、场景和运行配置。

### 6.5 内容发现与系统接入

领域包中的资产、场景和界面扩展通过稳定目录约定和 manifest 自动发现。新增独立内容目录不应要求并行任务共同修改中央注册表；发现器需要校验稳定 ID、内容类型、版本、依赖、能力状态和入口文件，并把错误定位到具体内容目录。

资产的独立预览只用于几何、材质和局部动作验收，不代表已经进入系统。一个可交互资产只有同时满足以下条件，才能标记为 `available`：

- 已被统一注册表发现，并能在创作工作台中作为资产引用。
- 已进入至少一个场景，在独立运行视图中按真实单位和地面基准展示。
- 交互锚点、碰撞、语义动作、React 界面和 3D 表现读取同一运行状态。
- 桌面和移动端均存在可发现的操作入口。
- 自动化验证和视觉验收覆盖系统内入口，而不是只覆盖独立 `preview.html`。

几何已经完成但库存挂接、权限、运行时动作或系统入口尚未完成的内容必须保持 `planned`。

## 7. 时间与调度

平台提供与渲染帧率解耦的固定仿真时钟：

- 暂停、继续和时间倍率。
- 固定步长更新。
- 一次性和周期性调度事件。
- 动作和流程超时。
- 可配置的离线推进策略。

离线收益、寿命、季节、修炼周期等属于工程规则；平台只提供时间机制。

## 8. 动作运行时

通用动作生命周期：

```text
queued → validating → running → completed
                    ├→ paused
                    ├→ cancelled
                    ├→ superseded
                    └→ failed
```

平台需要支持：

- 条件校验和权限校验。
- 资源预留和并发冲突检测。
- 可配置动作通道。
- 实时修改、取消替换和不可中断阶段。
- 目标消失、租约过期和运行暂停策略。
- `idempotencyKey` 与 `expectedRevision`。
- 完成效果的原子提交。

动作通道由领域包声明。平台可以提供 `movement`、`posture` 等建议通道，但不得假设所有工程都有类人角色。

## 9. Agent 控制与语义接口

Agent 不直接修改坐标、组件字段、资源账户或数据库。Agent 先获得观察，再从当前允许动作中选择语义动作。

### 9.1 控制租约

```http
POST /api/runs/{runId}/agents/{agentId}/control-sessions
POST /api/control-sessions/{id}/heartbeat
DELETE /api/control-sessions/{id}
```

租约返回短期 Token、权限范围、空闲过期时间、绝对过期时间和 `fencingEpoch`。

平台必须处理：

- 心跳续租。
- 空闲过期。
- 绝对最长控制时间。
- 玩家或管理员接管。
- Token 轮换与撤销。
- 旧控制器延迟请求隔离。
- 租约过期时正在执行动作的工程定义策略。

### 9.2 观察与动作

```http
GET  /api/runs/{runId}/agents/{agentId}/observation
GET  /api/runs/{runId}/agents/{agentId}/actions
POST /api/runs/{runId}/agents/{agentId}/actions
GET  /api/runs/{runId}/entities/{entityId}/state
GET  /api/runs/{runId}/events
```

观察结果由权限和工程定义共同投影，不能默认让 Agent 获得整个世界的全知状态。

CLI、HTTP API、`/llms.txt`、`/capabilities.json` 与路径级 `/skill.md` 必须继续由同一 capability registry 生成。平台不新增 MCP。

## 10. 物理、空间交互与导航

通用空间运行时提供可替换模块边界：

- 静态碰撞体。
- 动态刚体和可推动物体。
- 质量、摩擦和阻尼。
- 地面、斜坡和台阶检测。
- 射线选择、可见性和交互距离。
- 导航区域和路径规划。
- 第一人称、第三人称和自由视角。
- 动画状态机和动作混合。

某个工程可以完全不启用物理或导航。管理国家、家族谱系等工程仍能使用同一状态、关系、规则、事件和管理视图框架。

## 11. 工作区与界面

### 11.1 创作工作台

固定工作区，用于资产、场景、领域定义和规则配置。IDE 式界面只承担创作与调试。

### 11.2 游戏视图

固定运行视图框架，默认全屏三维画面。HUD、快捷操作和可见信息由工程配置。游戏视图由 WebGL 3D 视口和 React 界面层共同组成，不要求把所有游戏界面画进 3D 场景。

```text
/play/{runId}
```

### 11.3 管理工作区

平台提供通用管理视图框架，不提供固定“运营中心”业务模型。领域包可声明：

- 导航分组和页面。
- 实体列表、详情和关系图。
- 表单、表格、指标和图表。
- 允许执行的语义动作。
- 事件流和告警。
- 场景预览和实体定位。

```text
/manage/{runId}
```

赛博工厂可以把管理工作区命名为“运营中心”，宗门工程可以命名为“宗门大殿”，国家工程可以命名为“政务中心”；它们都由同一视图定义机制生成和扩展。

### 11.4 React 与 3D 混合界面

游戏界面采用分层组合：

```text
游戏视图根容器
├─ 3D 世界层
│  ├─ 场景、角色和物体
│  ├─ 光照、阴影和材质
│  ├─ 碰撞、拾取和射线检测
│  └─ 轮廓、路径、落点等空间反馈
├─ 世界锚定界面层
│  ├─ 角色头顶状态
│  ├─ 物体名称和交互标记
│  ├─ 伤害、产出或事件提示
│  └─ 将三维锚点投影到屏幕坐标的 React 组件
├─ 屏幕 HUD 层
│  ├─ 准星
│  ├─ 角色状态条
│  ├─ 当前目标和动作进度
│  ├─ 快捷栏
│  └─ 右侧首选交互与候选动作
└─ 面板与模态层
   ├─ 背包、角色和任务面板
   ├─ 对话、选择和确认界面
   ├─ 设置、暂停和帮助
   └─ 工程自定义 React 页面
```

#### 3D 世界层职责

- 管理 renderer、scene、camera 和帧循环。
- 提供三维对象拾取、遮挡、深度和世界坐标。
- 提供碰撞、导航和空间交互候选。
- 渲染必须参与景深或遮挡的世界内界面，例如真实显示器屏幕。
- 不直接维护任务、库存、按钮启用状态或领域业务文案。

#### React 界面层职责

- 渲染状态、按钮、表单、列表、图表、对话和设置。
- 使用标准布局、响应式 CSS、键盘焦点和无障碍语义。
- 根据运行时权限和动作候选决定可见、可用或禁用状态。
- 点击按钮时只提交语义动作，不能直接改 Three.js 对象或运行时数据。
- 允许领域包注册工程自定义 HUD 组件和管理组件。

#### 世界锚定 React 组件

世界锚定组件绑定实体或交互锚点。平台每次更新投影时提供屏幕坐标、是否在相机前方、是否被遮挡和距离信息；React 只负责展示。

世界锚定组件需要支持：

- 超出视野时隐藏或吸附到屏幕边缘。
- 被实体遮挡时隐藏、弱化或按工程规则继续显示。
- 根据距离缩放、聚合或省略。
- 多个标记重叠时进行避让和优先级排序。
- 不跟随 React 常规状态变化触发整个 3D 场景重建。

#### 状态与动作连接

3D 和 React 必须订阅同一个运行时状态源：

```text
输入或 React 按钮
→ 语义动作请求
→ 动作校验与运行时执行
→ 状态和事件变化
→ 3D 表现更新 + React UI 更新
```

禁止以下双向直改方式：

```text
React onClick → 直接修改 mesh.position
3D 点击事件 → 直接修改 React 本地库存数值
```

界面可以对连续交互提供临时预览状态，但最终结果必须由动作运行时确认。

#### 工程自定义 HUD

领域包可以声明 HUD 插槽和数据绑定：

- 左上、右上、左下、右下、顶部居中、底部居中。
- 准星周围和当前目标区域。
- 全屏面板和模态框。
- 世界锚定实体组件。

平台提供可复用基础组件，例如文本、数值、进度条、状态图标、动作按钮、动作列表、实体摘要、资源列表、事件列表和快捷栏。工程可以组合这些组件，也可以注册独立 React 组件，但不能替换动作权限校验。

#### 通用实体交互界面

平台提供统一的实体交互宿主，领域包或模型只声明交互内容和推荐呈现方式，不能为每个模型复制一套不兼容的弹窗生命周期。交互定义至少包含：

- 面向用户的实体名称、图标、摘要和本地化动作名称。
- 轻量快捷动作、标准面板、配置面板或工程自定义 React 面板等呈现类型。
- 查询投影、候选动作、选择状态、提交状态、错误和完成反馈。
- 可见权限、可执行权限和管理权限；不可见能力不能只通过禁用按钮泄露给无权限用户。
- 桌面快捷键、手柄/触摸入口和关闭后的输入恢复策略。

平台只提供“打开”“关闭”“提交”等通用回退文案。模型或领域动作必须覆盖为“制作咖啡”“接水”“取走商品”“打开笔记本”等真实业务名称，不能把不同设备统一显示为“打开显示器”。

复杂实体默认使用视口中央模态面板：打开时隐藏或弱化无关 HUD、暂停角色移动并释放指针锁定；`Esc` 关闭最高层面板，关闭后按进入前状态恢复游戏输入。简单的即时动作可以继续使用准星附近或右侧快捷提示。工程可以通过主题令牌、插槽和自定义 React 扩展改变视觉风格，但不能绕过统一焦点、快捷键、权限和动作提交机制。

配置面板是同一实体交互宿主中的权限视图，而不是第二套页面。普通用户只看到被授权的消费、取用或操作能力；补货、定价、商品配置、维护和调试等管理能力仅在主体持有相应凭证或角色权限时出现。容量是约束，不替代“当前包含哪些实体、各自数量、价格和归属”的配置。

#### React 界面扩展层级

平台需要同时满足不写代码的工程配置和复杂游戏的定制需求，因此 React 界面分为三层：

1. **声明式界面定义**：领域包通过可序列化配置选择插槽、组件、查询、字段、格式和动作，不要求编写前端代码。
2. **平台基础组件**：SolidLoom 提供具有统一主题、布局、焦点、快捷键和无障碍行为的 React 组件库。
3. **工程 React 扩展**：复杂工程可以注册独立 HUD、面板和模态组件，用于声明式配置无法表达的交互，但扩展只能通过受控运行时接口读写世界。

工程 React 扩展属于领域包或工程资产，不进入 SolidLoom 通用导航，也不能让平台源码依赖“员工”“宗门”“国家”等领域组件。未安装某个工程扩展时，平台仍能使用声明式基础组件显示该工程的通用数据和动作。

首期可提供以下只读查询和动作接口；具体命名可以在实现阶段调整：

```ts
useRun(runId)
useEntity(entityId, projection)
useComponent(entityId, componentType)
useRelationQuery(query)
useMetric(metricId, scope)
useAvailableActions(subjectId, targetId?)
useActionProgress(actionId)
useSelection()
useWorldAnchor(entityId, anchorName?)
dispatchAction(request)
dispatchViewCommand(command)
```

其中：

- `dispatchAction` 提交会改变世界语义状态的动作，必须经过权限、前置条件、资源预留和并发校验。
- `dispatchViewCommand` 只控制镜头聚焦、选中、高亮、面板开关和调试可视化等表现状态，不能改变领域状态。
- 查询接口返回权限裁剪后的投影，不向组件暴露任意数据库访问能力。
- 工程组件不得直接获得可变 Three.js 场景对象、数据库连接或服务端内部仓库实例。

#### 3D 与 React 联动

3D 交互和 React 控件需要双向联动，但必须区分领域动作与表现命令：

```text
3D 拾取实体
→ 更新当前目标或选择
→ React 显示实体摘要和可用动作

React 点击“定位”
→ 发送表现命令
→ 3D 镜头聚焦并高亮实体

React 点击“打开电脑”
→ 提交语义动作
→ 运行时改变电脑和屏幕关节状态
→ 3D 播放开盖动画，React 更新按钮与进度
```

React 可以绘制角色状态、物体状态、操作按钮、快捷栏、任务、背包、对话、设置和经营面板。3D 可以向 React 提供当前瞄准对象、空间距离、遮挡结果、交互锚点和相机模式；React 不自行推断碰撞或空间可达性。

对于必须出现在三维世界表面的界面，平台需要区分两种模式：

- **世界表面材质**：例如电脑显示器内容，需要参与透视、遮挡、光照或后处理，由 3D 层渲染；内容可以由 React 离屏渲染结果或专用纹理源提供。
- **世界锚定 React 界面**：例如实体名称和交互提示，保持二维可读性，由 React 覆盖层渲染并跟随三维锚点。

二者不能通过简单 DOM 层级互相替代；工程需要明确选择所需的空间表现。

#### 界面状态边界

界面状态分为三类：

- **运行时领域状态**：实体状态、资源、关系、动作和流程，保存在运行实例中并产生事件。
- **玩家视图状态**：当前选择、打开面板、筛选条件、镜头模式和 HUD 布局，可按玩家或本机保存。
- **瞬时交互状态**：悬停、按下、拖拽预览和焦点，留在 React 或输入系统中，不写入世界存档。

工程组件不得把瞬时界面状态伪装成领域状态，也不得只在组件本地修改需要持久化和审计的业务数据。多人或多 Agent 场景中，不同观察者可以拥有不同的视图状态，但必须看到权限允许的同一份运行时事实。

#### 指针锁定与事件命中

- 纯展示 HUD 默认 `pointer-events: none`，不能挡住 3D 视口。
- 可点击 React 控件明确启用事件命中。
- 第一或第三人称锁定鼠标时，准星交互通过快捷键执行。
- 打开需要鼠标操作的面板时，暂停或临时释放指针锁定。
- 关闭面板后按工程配置恢复游戏输入。
- `Esc` 始终能退出指针锁定或关闭最高层模态界面。

3D 视口与 React 控件之间必须有统一输入仲裁：当指针命中可点击 React 控件时，不得同时触发 3D 拾取；模态框打开时，游戏移动输入按工程配置暂停；文本输入获得焦点时，`WASD` 等按键不得继续驱动角色。

相机模式属于玩家视图设置。第一人称、第三人称和自由视角的选择应放入统一设置面板；运行视图顶层只保留必要的图标入口，不长期占用画面展示调试标题或相机模式切换条。设置面板必须保留移动端可触摸入口。

#### 性能边界

- 3D 帧循环不能驱动整棵 React 组件树每帧重渲染。
- 高频相机和投影数据使用独立订阅、批量更新或节流。
- 领域状态只在真实状态修订变化时更新 React。
- 大型列表、事件流和实体面板使用分页或虚拟化。
- 3D 资源生命周期由 3D 系统负责，React 卸载时必须显式释放对应订阅。

### 11.5 移动端产物

移动端是正式运行产物，不是桌面页面缩小后的附属预览。平台需要从输入、布局、性能和运行方式上保留手机与平板能力。

#### 产品边界

- **创作工作台**：首期桌面优先；手机只要求查看、审批、轻量参数调整或调试运行实例，不要求承载完整三维建模工作流。
- **游戏视图**：必须支持手机和平板游玩，包括触摸移动、视角、选择和语义动作。
- **管理工作区**：必须支持响应式列表、指标、关系、事件和操作页面。
- 桌面与移动端使用同一运行时、领域包、权限、动作和事件协议，不复制一套移动端业务规则。

#### 响应式 React 布局

- `/play/{runId}` 和 `/manage/{runId}` 使用同一路由与组件体系，根据容器宽度、输入能力、方向和安全区域切换布局。
- HUD 插槽允许定义桌面、横屏移动端和竖屏移动端变体；未定义变体时使用平台提供的自动降级布局。
- 桌面侧栏在窄屏中转换为抽屉、底部面板或全屏页面，不能继续占用固定宽度。
- 状态和动作按优先级折叠；核心交互必须在单手可达区域内，次要信息进入展开面板。
- 使用 `safe-area-inset-*` 避开刘海、圆角和系统手势区；不得用固定像素假设可用视口。
- 触摸目标建议不小于 44 CSS px，并为按下、禁用、执行中和失败状态提供明确反馈。
- 屏幕旋转、分屏和软键盘出现时，3D 视口、HUD 与模态界面需要重新布局，不能丢失当前动作或选择。

#### 统一输入语义

运行时和角色控制不得直接依赖 `WASD`、鼠标移动或 Pointer Lock。平台先定义输入语义，再由设备适配器产生输入：

```text
moveVector
lookDelta
primaryInteract
secondaryInteract
openActionList
openPanel
cancel
sprint
crouch
```

输入适配器至少预留：

- 键盘与鼠标。
- 手柄。
- 触摸虚拟摇杆与按钮。
- 触摸拖动视角、点按选择和双指缩放。
- 可选陀螺仪视角；默认关闭并由用户明确授权。

移动端默认左侧控制移动，右侧空白区域拖动视角，右侧 React 动作区显示当前首选交互。触摸 HUD 时不得同时旋转镜头或触发 3D 拾取。所有快捷键动作都必须存在可发现的触摸入口，不能让某项核心能力只在键盘上可用。

#### 移动端 3D 性能等级

平台需要根据设备能力和用户设置选择质量等级，而不是维护另一套场景：

- 限制设备像素比和动态分辨率。
- 按等级调整阴影、实时灯光、后处理、反射和抗锯齿。
- 使用 LOD、实例化、视锥裁剪、遮挡策略和按需动画更新。
- 纹理采用移动端友好的压缩和尺寸上限；大场景按区域或引用资产延迟加载。
- 进入后台、页面隐藏或系统低功耗状态时暂停高频仿真表现和渲染；恢复时从权威运行时状态重建画面。
- 正确处理 WebGL 上下文丢失、内存压力和资源释放，不能要求用户刷新页面才能恢复。

首期以可交互稳定性优先：中档手机建议维持至少 30 FPS；达不到目标时优先降低表现质量，不能降低动作校验、状态正确性或权限安全性。

#### 本地优先运行方式

移动端不得迫使工程迁移到云端。平台预留两种本地优先方式：

1. **设备内运行**：轻量工程可通过移动浏览器或 PWA 在设备内加载领域包、场景和本地存档。
2. **局域网连接**：手机作为游戏或管理客户端，通过显式配对连接用户电脑上的 SolidLoom 本地运行时。

局域网连接需要用户主动开启、短期配对凭据、来源限制、权限作用域和可撤销会话。桌面运行时保持权威状态；移动端断线重连后从快照和事件游标恢复，不能靠本地 React 状态猜测世界变化。默认配置不开放公网端口，也不依赖云端账户。

#### 移动端界面扩展约束

- 声明式 HUD 组件必须提供响应式行为和触摸语义。
- 工程 React 扩展需要声明支持的断点、输入设备和方向；不支持时由平台显示兼容布局或基础组件回退，不能渲染不可用空白页。
- 工程扩展不能直接读取设备标识、传感器或剪贴板；需要平台权限接口和用户授权。
- 移动端视觉适配不能复制领域计算逻辑，所有状态和动作继续通过查询投影与 `dispatchAction` 获取。

## 12. 查询、投影与权限

管理视图和 Agent 观察不能直接遍历任意数据库表。平台需要通用查询与投影层：

- 按实体类型、组件字段和关系查询。
- 按权限过滤字段和实体。
- 聚合资源、指标和事件。
- 保存工程定义的查询视图。
- 支持分页、排序和增量更新。

权限由角色、能力和作用域组成。工程定义角色名称；平台执行统一校验。

## 13. 资源账本与幂等效果

平台提供通用资源账本，但不预设货币、库存或会计科目。资源变化需要：

- 明确来源实体、目标实体和资源类型。
- 支持预留、提交、释放、产生、消耗和转移。
- 使用 `sourceActionId` 或 `sourceEventId` 防止重复结算。
- 记录变更前后数量和规则来源。
- 在动作完成效果中原子提交。

只有工程选择启用资源类型时才使用这套能力。

## 14. 持久化与版本迁移

继续使用本地 SQLite。逻辑数据至少覆盖：

- 领域包和版本。
- 资产与版本。
- 场景和引用。
- 运行配置。
- 运行实例与实体快照。
- 关系、动作、流程和调度项。
- 通用资源分录和指标投影。
- 控制租约。
- 追加式事件日志。

运行状态使用“快照 + 事件”。领域包升级必须提供兼容范围和迁移路径；没有迁移方案时不得静默升级已有存档。

## 16. 通用性验收

平台内核完成后，至少用四个最小领域包验证抽象。每个领域包都不得修改平台共享类型和动作运行时：

1. **工厂包**：员工工作增加订单进度并消耗体力，喝水消耗库存。
2. **家族包**：成员具有血缘和婚姻关系，继承流程转移财产并改变关系。
3. **宗门包**：弟子消耗灵石开始修炼流程，完成后增加修为和宗门贡献。
4. **国家包**：行政区通过管辖关系隶属国家，政策流程消耗预算并改变稳定度指标。

如果四个包能仅靠领域定义、规则、视图配置和授权扩展实现核心闭环，平台抽象才算成立。

React 与 3D 混合界面还需要满足以下通用验收：

- 领域包能够仅靠声明式配置在游戏视图中展示状态和语义动作按钮。
- 工程可以注册独立 React HUD 或面板，而不修改通用游戏视图组件。
- 3D 选择实体后，React 信息和可用动作随运行时投影更新。
- React 发起领域动作后，3D 表现和 React 状态都由同一个运行时事件更新。
- React 的镜头聚焦和高亮只改变表现状态，不产生领域事件。
- React 控件、3D 拾取、指针锁定和键盘输入不会重复响应同一次输入。
- 相机帧更新不会导致整棵 React 界面树逐帧重渲染。
- 同一个工程可以在桌面鼠标键盘和手机触摸输入下完成同一条核心动作闭环。
- 手机竖屏和横屏切换后，HUD、3D 视口和动作状态保持连续，不丢失运行时事实。
- 手机端通过局域网连接桌面运行时时，断线重连不会重复提交动作或丢失已确认事件。
- 未提供工程专用移动组件时，平台基础 React 组件仍能展示关键状态并执行语义动作。

模型引用可以声明通用分段动作程序。每一步只描述持续时间、目标特征或目标引用，以及相对位置、缩放和可见性变化；Web 运行时负责插值、连续渲染、执行状态、禁用重复提交和当前运行实例内的结果恢复。该机制不得包含“堆垛机”“货架”等领域名词，领域包仅通过配置组合出取货、机械臂搬运、传送带流转或自动门联动。涉及所有权、库存、资金或凭证的最终提交仍必须由领域动作事务完成，不能仅凭 3D 动画推断业务事实。

## 17. 首期范围

### 第一阶段：通用运行时骨架

- 领域包清单与版本。
- 自定义实体、组件和关系。
- 通用状态、动作、规则和事件。
- 固定仿真时间。
- Agent 控制租约。
- 通用查询和基础管理视图。
- 游戏视图和管理视图的移动端响应式骨架、触摸输入适配与基础质量等级。
- 本地快照与事件持久化。

### 第二阶段：赛博工厂垂直闭环

使用独立的赛博工厂领域包验证“走到工位、工作、口渴、喝水、消耗库存、完成任务、产生收入”的完整链路。

### 第三阶段：跨领域验证

实现家族、宗门和国家的最小验证包，重点验证关系、长流程、资源和指标，而不是制作完整游戏内容。

## 18. 首期非目标

- 把工厂、员工、公司、库存或财务字段写入平台实体基类。
- 为每种工程复制一套动作和 Agent API。
- 大规模多人在线服务。
- 默认云端部署和跨设备同步。
- 完整通用游戏引擎替代品。
- 生产级复杂布料、流体和破坏物理。
- 不受限制的任意脚本执行。
- 绕过语义动作直接修改数据库的 Agent 接口。
