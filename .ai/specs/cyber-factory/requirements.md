# 赛博工厂工程需求规格

> 状态：需求梳理中。
>
> 实现状态：本文新增能力均为 `planned`，不代表当前版本已经可用。
>
> 依赖：[SolidLoom 可运行世界与通用管理系统需求规格](../solidloom-runtime-platform/requirements.md)

## 1. 工程定位

赛博工厂是使用 SolidLoom 通用平台搭建的领域工程，不是平台内核。它负责提供办公室和工厂所需的实体定义、组件、关系、资源、动作、流程、规则、视图、场景和初始配置。

删除赛博工厂领域包后，SolidLoom 平台仍应能够运行其他工程；升级赛博工厂规则不应要求修改平台通用实体类型。

## 2. 首期目标

首期使用办公室场景验证一个 Agent 能够完成以下闭环：

```text
申请员工控制租约
→ 获取自身和附近环境状态
→ 走到分配的工位并坐下
→ 打开笔记本并开始任务
→ 有效工作增加任务进度
→ 工作导致口渴和疲劳
→ 离开工作后停止增加任务进度
→ 前往饮水机喝水
→ 公司饮用水库存被扣减
→ 员工状态恢复
→ 返回工位继续工作
→ 完成任务并产生一次收入
```

## 3. 领域定义

### 3.1 实体类型

- 公司。
- 员工。
- 场所和房间。
- 工位。
- 椅子。
- 笔记本和其他办公设备。
- 饮水机、咖啡机和零食柜。
- 仓储货架、托盘、周转箱、物流推车和自动取货设备。
- 任务和订单。
- 流水线、机器和生产单元。

这些实体通过赛博工厂命名空间注册，不进入平台通用实体基类。

### 3.2 关系类型

- 员工任职于公司。
- 员工分配到岗位。
- 员工分配到任务。
- 工位属于场所。
- 员工占用工位或椅子。
- 设备属于公司或场所。
- 流水线包含生产单元。

### 3.3 员工状态组件

- 体力。
- 水分。
- 饱腹。
- 压力。
- 专注。
- 情绪。
- 健康。
- 工作动力。

状态字段、阈值、派生状态、更新速率和可见权限全部由本领域包定义。

### 3.4 资源类型

- 现金。
- 饮用水。
- 咖啡豆和零食。
- 生产原料。
- 产品库存。
- 其他消耗品。

桌椅、电脑、咖啡机和机器属于带资产组件的实体，不要求平台把所有物体放进固定资产表。

### 3.5 指标

- 任务完成率。
- 工作效率。
- 员工满意度。
- 公司估值。
- 产能利用率。

## 4. 动作与交互

首期动作：

- 行走和停止。
- 坐下和起身。
- 推动椅子。
- 打开、合上和使用笔记本。
- 开门和关门。
- 开始工作和停止工作。
- 接水和喝水。
- 吃零食。

后续动作：

- 制作咖啡。
- 补充耗材。
- 启动和停止机器。
- 按货位补货、预占、自动取货、出库和取消仓储任务。
- 补料、质检、排障和维护。

动作前置条件、通道占用、持续时间和效果由赛博工厂规则定义，但由平台动作运行时统一执行。

## 5. 工作与价值创造规则

处于工位附近或坐在椅子上不等于正在创造价值。增加任务工作量至少需要：

```text
正在执行工作动作
+ 已分配有效任务
+ 位于正确工位
+ 所需设备可用且占用成功
+ 员工具备岗位能力
+ 任务仍有剩余工作量
+ 没有冲突动作
```

建议计算关系：

```text
有效工作时间
× 员工技能系数
× 专注系数
× 设备效率
× 环境影响
= 任务工作量
```

首期任务完成后按配置产生固定收入。后续可以扩展为：

```text
工作量 → 交付物或产品 → 验收 → 应收收入 → 现金到账
```

离开工位、停止工作、喝水或休息时不增加任务进度。工资、租金和基础费用可以继续发生。

## 6. 消费与库存规则

喝水、吃零食和使用耗材采用：

```text
检查权限与库存
→ 预留资源
→ 执行动作
→ 到达消费提交点
→ 提交资源扣减
→ 更新员工状态
→ 发出领域事件
```

提交点前取消动作则释放预留；提交点后取消不退还资源。所有效果使用 `sourceActionId` 和幂等键，防止重复扣减。

商品、原料、凭证和其他可转移对象统一视为实体。存入、取出、购买、补货和自动取货不是复制数量，而是在动作提交点原子更新实体所有权、容器归属、空间挂接和库存投影。凭证可以由背包、角色、组织或外部容器持有；平台只校验当前操作主体是否满足作用域、权限和有效期，不把“背包”写死为唯一来源。

### 6.1 自动仓储与取货

仓储货架使用稳定货位地址。自动取货设备首期采用巷道堆垛机形态，执行：

```text
校验货位和权限
→ 预占货物、目标货位与设备
→ 横移到目标跨
→ 升降到目标层
→ 伸叉并挂接托盘或周转箱
→ 收叉并运送到出库位
→ 原子提交所有权、容器归属和空间挂接
→ 释放预占并产生审计事件
```

上货使用同一套校验和状态机反向执行。任务必须支持取消、失败恢复、设备占用冲突、目标货物消失和运行实例暂停；进入不可中断提交阶段后不能伪装成已取消。单纯播放堆垛机动画不算库存动作完成。

交互试验场的首期本地闭环应先验证可观察的操作体验：货架在固定地址展示货物，操作员通过设备面板选择货位，堆垛机依次执行横移、升降、伸叉、托起、回程和出库，货物随机构运动并在出库位等待领取。领取后，当前运行实例中的货物不可再次领取。该闭环用于验证模型、动作程序和 React 操作面板；跨进程库存事务、任务恢复、并发预占和审计仍按上述正式要求实现，不能因本地动画已运行而宣称完成。

## 7. 管理工作区

赛博工厂通过 SolidLoom 通用管理视图框架配置“运营中心”：

- 员工状态、岗位和当前动作。
- 工位和设备占用。
- 任务、订单和交付进度。
- 库存和资产。
- 收入、支出和现金流。
- 流水线状态和异常。
- Agent 控制租约。
- 审计事件和场景预览。

这些页面属于赛博工厂领域包，不进入 SolidLoom 固定导航。

### 7.1 游戏 HUD

赛博工厂游戏界面使用平台的 React 与 3D 混合界面机制：

- 3D 层渲染办公室、角色、设备、碰撞和空间选择反馈。
- 中央使用轻量准星；瞄准可交互实体时显示目标反馈。
- 右侧使用 React 动作列表展示“坐下”“打开电脑”“喝水”等当前可用动作。
- 左下角使用 React 状态组件展示体力、水分、饱腹、压力等工程定义状态。
- 顶部显示当前任务或目标，但不持续展示冗长操作说明。
- `Tab` 打开员工状态、任务和个人物品面板。
- `Esc` 退出指针锁定并打开暂停界面。

所有按钮都提交赛博工厂语义动作；按钮不能直接修改模型关节、库存或员工状态。3D 场景中的电脑屏幕等真实世界表面可以继续由 3D 材质呈现，其开关状态仍来自同一运行时。

赛博工厂可以使用工程 React 扩展绘制更完整的游戏界面，例如员工状态详情、工作任务、工位操作、设备控制、背包和暂停设置。这些组件通过平台查询 hook 读取赛博工厂领域投影，通过 `dispatchAction` 提交动作；不得在组件中复制工作计费、库存扣减或员工状态计算规则。

瞄准电脑、椅子、门或饮水机时，3D 层只负责提供目标、距离、遮挡和可达性候选，右侧 React 交互区根据运行时返回的可用动作显示对应按钮。目标状态变化后，例如笔记本已打开，“打开”应自动替换为“合上”或其他工程定义动作。

轻量动作继续使用右侧快捷提示；打开零食售货机、咖啡机、饮水机、仓储货架等需要选择内容的实体时，使用视口中央的通用实体交互面板，并隐藏无关 HUD、释放指针锁定和暂停角色移动。`Esc` 关闭面板。商品、饮品、仓储格口和设备状态由各模型配置注入；平台不写死列表、价格或动作名称。

零食售货机的普通用户视图只提供选择和取用/购买；补货、商品配置、定价、维护和破解属于权限裁剪后的管理或特殊动作。咖啡机、饮水机、货架和其他设备使用同一交互宿主，但可以注册各自的图标、布局、动作标签和工程 React 扩展。

### 7.2 移动端游戏与管理界面

赛博工厂需要使用平台移动端能力完成同一套办公空间闭环：

- 左侧虚拟摇杆控制角色移动，右侧空白区域拖动控制视角。
- 当前首选交互和候选动作放在右侧拇指可达区域，不依赖键盘快捷键或 Pointer Lock。
- 体力、水分、饱腹和压力等状态在窄屏中显示为紧凑摘要，点击后打开详细底部面板。
- 员工、任务、库存、资金和流水线管理页面在手机上使用列表、卡片摘要和分层详情，不强行压缩桌面宽表格。
- 手机端动作仍经过赛博工厂权限、工作规则、资源预留和幂等校验，不能维护独立的简化规则。
- 局域网客户端断线时停止接受需要实时空间反馈的新动作；重连后先同步员工、设备、资源和控制租约状态。

## 8. Agent 权限

赛博工厂首期建议权限：

```text
observe:self
observe:nearby
act:self
operate:assigned-device
manage:team
manage:company
debug:state
```

普通员工 Agent 不能默认读取公司全部资金、其他员工隐私或不可见场景状态。

## 9. 首期验收标准

- 赛博工厂领域包可以独立启用和禁用。
- 平台共享实体类型中不存在员工、公司、库存和收入专有字段。
- 非工作动作不会增加任务进度。
- 离开工位后任务进度停止增长。
- 库存不足时喝水或消费动作失败。
- Token 过期后 Agent 不能继续控制员工。
- 玩家接管后旧 Agent 请求不能提交。
- 网络重试不会重复增加任务进度、收入或扣减库存。
- 动作、状态、关系、资源和指标变化均能追溯到领域事件。
- 运营中心由赛博工厂视图定义生成或扩展，而不是写死在平台导航中。
- 交互资产必须在系统内场景按真实比例、正确地面基准和可达位置验收；独立模型预览不能代替运行视图验收。
- 零食售货机、咖啡机、饮水机、仓储货架和自动取货设备使用同一交互宿主与动作运行时，但保持各自业务动作和权限视图。

## 10. 后续范围

### 办公室经营

- 多员工、岗位和工位。
- 工资、租金和耗材。
- 饮水机、咖啡机、零食柜、厕所和休息区。
- Agent 自主安排工作、恢复和协作。

### 工厂流水线

- 原料和产品库存。
- 工序依赖与生产节拍。
- 设备产能、故障和维护。
- 质检、返工与报废。
- 停机成本和内部物流。

## 11. 待确认决策

1. 首期收入是否固定在任务完成时一次结算。
2. 员工状态首期只影响效率，还是可以导致拒绝工作、离职或生病。
3. 首期玩家是管理员兼现场角色，还是只有管理员自由视角。
4. 正式运行实例是否允许在运行过程中升级引用资产版本。
5. 关闭本地运行实例后是否暂停，不计算离线进度。
