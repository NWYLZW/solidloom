# Web 前端模块边界

SolidLoom Web 采用“页面编排、领域状态、展示组件、3D 系统、共享模型”五层结构。拆分的目标不是追求小文件，而是让并行开发时不同功能尽量落在不同文件中，并让合并冲突集中在稳定的装配入口。

## 依赖方向

```text
App.tsx（页面编排）
  ├─ components/（展示与局部交互）
  ├─ articulation/（关节动作领域）
  ├─ navigation.ts / roomSurfaces.ts / modelReferences.ts（纯领域计算）
  └─ Viewport3D.tsx（3D 系统装配）
       └─ articulation/runtime.ts 等纯运行时

packages/shared（数据契约、schema、示例、capability registry）
packages/cad-engine（几何与图结构校验）
```

依赖只能从上向下：展示组件不读取 API、不保存模型；纯领域模块不依赖 React 或 DOM；共享包不依赖 Web 应用。

## 哪些应该复用

| 类型 | 位置 | 复用规则 |
| --- | --- | --- |
| 顶部栏、状态栏、选择摘要、模型动作面板 | `src/components/` | 可在不同工作区复用；通过 props 接收文案和事件，不读取全局编辑器状态 |
| 关节动作请求、关键帧采样、动作状态机 | `src/articulation/` | 模型动作、场景角色与后续时间轴共同复用；运行时算法必须可脱离 Three.js 测试 |
| 引用解析、导航、房间表面、材质解析、网格操作 | `src/*.ts`，后续按领域迁入同名目录 | 保持纯函数；页面、视口和服务适配器都可以调用 |
| 模型、特征、关节、动画、材质的数据契约 | `packages/shared/` | Web、CLI、服务端与 CAD 引擎共用；变更时同步 schema 和 capability registry |

## 哪些独立维护

| 模块 | 独立原因 | 不应承担的职责 |
| --- | --- | --- |
| `App.tsx` | 负责选中状态、历史、保存和各区域装配 | 不写局部组件 DOM，不实现插值、几何或导航算法 |
| `Viewport3D.tsx` | 管理 renderer、scene、camera 生命周期 | 不维护表单文案，不保存业务数据，不定义动作数据契约 |
| `components/*.tsx` | 负责一个明确界面区域 | 不直接调用 HTTP API，不复制领域计算 |
| `components/*.css` | 与同名组件共同演进 | 不在全局 `styles.css` 覆盖单个组件的私有布局 |
| `styles.css` | 只保留设计变量、工作区网格与真正共享的基础控件 | 不继续收纳新业务组件样式 |

## 文件拆分准则

1. 一个组件拥有自己的 JSX、局部交互和同名 CSS；同一方向的间距只由一层持有。
2. 跨组件共享的状态进入领域 hook；可用输入直接计算的逻辑进入纯函数模块。
3. `App.tsx` 新增功能时先组合现有组件；超过一个完整界面区域的 JSX 必须抽成组件。
4. `Viewport3D.tsx` 新增系统时只保留生命周期装配；插值、碰撞、拾取、相机策略分别进入独立运行时模块。
5. 只在两个调用方真实需要同一语义时抽公共组件，避免只有外观相似却行为不同的过度复用。
6. 新组件的样式不回填到 `styles.css`；共享尺寸和颜色使用既有 CSS 变量。

## 当前拆分状态

- 已独立：顶部栏、状态栏、选择摘要、模型动作面板、关节动作 hook 与关键帧运行时。
- 已有纯领域模块：材质、网格操作、模型引用、导航、房间表面、树 URL 状态。
- 后续触碰项目树、检查器、对象工具浮层或导航 HUD 时，应先迁入各自目录，再增加功能；不要继续扩展 `App.tsx`。
- 后续触碰相机、拾取、变换、碰撞或注释投影时，应先从 `Viewport3D.tsx` 抽出对应系统，再增加功能。

这样安排允许多个开发者分别修改项目树、检查器、动作系统和 3D 运行时，装配入口通常只发生少量 import 与 props 变化。
